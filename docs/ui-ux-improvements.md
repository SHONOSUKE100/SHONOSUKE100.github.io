# UI/UX 改善レビュー

最終更新: 2026-08-10

## 対象と方法

現状実装の全ルート（トップ、About、Work、Writing、記事詳細、Contact、Memory Map）を対象に、情報設計、モバイル操作、キーボード操作、非JavaScript時の到達性、コンテンツの信頼性をレビューした。ローカル開発サーバーのバックグラウンド起動は環境上失敗したため、ソースコードと静的ビルド結果を中心に確認している。

## 優先度の定義

- **P0**: 目的達成、信頼性、基本的な利用可否を阻害する。
- **P1**: 操作性、アクセシビリティ、モバイル体験を明確に下げる。
- **P2**: 内容が増えたときの発見性・完成度を高める。

## 改善項目

| 優先度 | 課題 | 影響 | 対応 |
| --- | --- | --- | --- |
| P0 | Contact とフッターに仮の連絡先が残っている | 問い合わせ先の信頼性を損ない、リンク先も目的を果たさない | デザイン資料に記載された連絡先を共通設定へ集約し、すべての表示箇所で参照する |
| P0 | Memory Map は JavaScript / WebGL が使えないと、記録本文に到達できない | 地図を利用できない人がコンテンツを読めない | 同じ記録を静的な一覧・詳細リンクでも表示し、JavaScript 有効時だけ補助的に地図と連動させる |
| P1 | フォーカス表示が定義されていない | キーボード利用者が現在位置を追えない | すべてのリンク・ボタンに高コントラストな `:focus-visible` を追加する |
| P1 | 320〜375px 幅でナビゲーションが横スクロール前提 | メニュー項目の存在に気づきにくく、意図しない横操作になる | モバイルでは折り返し表示にして、全リンクを常に見える状態にする |
| P1 | Map のフィルター結果が視覚的にしか分からない | スクリーンリーダー利用者が結果件数を把握できない | ライブリージョンで表示件数と選択中カテゴリを通知する |
| P1 | 詳細カードの複数画像ギャラリーは位置の変化が読み上げられない | ボタンで写真を移動しても現在枚数が分かりにくい | 現在位置を `aria-live` で通知し、前後ボタンの無効状態を管理する |
| P2 | 実績カードと記事一覧の次アクションが弱い | 興味を持った内容を深掘りしにくい | 実績詳細または外部公開先が揃い次第、カード全体ではなく明示的なリンクを追加する |
| P2 | 画像素材は初期用SVGで、実際の写真・実績画像は未投入 | ポートフォリオとしての説得力が限定的 | 写真や実績の公開許可を確認後、WebP/AVIF と代替テキストを追加する |

## 今回実装する範囲

P0 と P1 を実装する。P2 は実データ・公開先の確定を必要とするため、コンテンツ収集後に対応する。

## 完了条件

- 連絡先が全ページで同一の設定値を使う。
- JavaScript がなくても Memory のタイトル、概要、場所、記録本文へ到達できる。
- フィルター、マーカー、写真ギャラリーをキーボードで操作でき、状態が通知される。
- 375px 幅で、ナビゲーションの全項目を横スクロールなしで確認できる。
